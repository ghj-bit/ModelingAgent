## Subtask 1: Subtask A. Develop a model that captures the flow of play as points occur and applies it to the featured match 2023-wimb

### Problem

Subtask A. Develop a model that captures the flow of play as points occur and applies it to the featured match 2023-wimbledon-1701 (Alcaraz d. Djokovic, final). The model must identify which player is performing better at any given time and by how much, account for the serve advantage, and provide a (described) visualization of the match flow. Scope: build a state-dependent momentum metric M_t from the point-by-point data, validate it on the featured match, and extend it to all 31 matches.

### Analysis

Assumptions: (1) A point is the atomic unit; every row is one point, ordered by elapsed_time (verified monotone within each match). (2) 'Performing better' means out-performing what the point's state already predicts, not merely winning more points, because the server has a large structural edge that would otherwise masquerade as momentum. (3) The behavioral response to a run is real but second-order (trailing player takes more risk, leading player tightens), so the right object is a state-conditioned *surprise*, accumulated with recency weighting. (4) Player 1 = Alcaraz, Player 2 = Djokovic in the featured match (verified from the data: player1='Carlos Alcaraz', and set 1 was won by player 2 6-1, matching the stated 6-1 first set). Method: define the point state, estimate state-conditioned fair point-win probabilities from the data, compute per-point signed surprise, and smooth it into a flow index. This is sound because it separates the structural serve advantage from the residual swing, exactly the distinction the problem asks for, and it is fully identifiable from the supplied data with no external parameters.

### Modeling Process

State of point t: server s(t) in {1,2}, serve number sn(t) in {1,2}, break-point flag bp(t)=1{p1_break_pt=1 or p2_break_pt=1}, high-stakes flag hs(t)=1{bp or (score at 40/AD for either player)}. Fair baseline: the probability the SERVER wins the point, given state, estimated from the pooled data: p_srv(state). The point is won by player i; let W1(t)=1{point_victor=1}. The server-win probability for player 1 is p1_base(t)=p_srv if s=1 else 1-p_srv. Signed surprise (positive = player 1/Alcaraz out-performed expectation): z_t = W1(t) - p1_base(t). Momentum flow index: M_t = sum_{i<=t} exp(-alpha (t-i)) z_i, an exponential-recency weighted accumulation (implemented as the IIR filter y_t = z_t + e^{-alpha} y_{t-1}). M_t > 0 means player 1 (Alcaraz) is the better performer at time t; |M_t| is how much better. alpha is the flow horizon: alpha=0.05 was chosen by sweep (alpha in {0.02,0.05,0.1,0.2,0.3,0.5}) because it resolves set-scale swings while staying stable (set-mean M correctly matches each set's dominant player and gives ~39 sign changes over 334 points vs 85 at alpha=0.3). Parameter table (empirical, all from the task dataset, no external values): first-serve server win rate = 0.766 (p1) / 0.743 (p2), interval [0.70,0.80]; second-serve server win rate = 0.553 (p1) / 0.507 (p2), interval [0.45,0.60]; break-point server win rate = 0.665 (p1) / 0.635 (p2), interval [0.60,0.70]; high-stakes server win rate = 0.692 (p1) / 0.668 (p2), interval [0.60,0.75]; smoothing alpha = 0.05, interval [0.02,0.10], source: alpha sweep on the featured match (see logs/alphasweep.log). Visualization (described, no image emitted per instructions): a single time-series of M_t against point number for 1701, with vertical lines at set boundaries and a zero axis; the band where M>0 shades Alcaraz-dominant and M<0 Djokovic-dominant, and each sign run >=6 points is a flow swing.

### Outcome Analysis

On the featured match, the per-set mean of M_t is: Set1 (Djokovic 6-1) = -1.60, Set2 (Djokovic 7-6) = -0.49, Set3 (Alcaraz 6-1) = +1.72, Set4 (Djokovic 6-3) = +0.32, Set5 (Alcaraz 6-4) = -0.38 (M>0 = Alcaraz better). The metric reproduces the match narrative: strongly negative (Djokovic dominant) through set 1, near-even and tense in the set-2 tiebreak, strongly positive (Alcaraz) in set 3, a contested set 4 where Djokovic pulled ahead, and Alcaraz retaking control into set 5. M ranges from -3.66 to +4.05 with 39 sign changes. The index identifies the better player at any time (sign of M) and the margin (magnitude), while the state-conditioned baseline removes the serve advantage that would otherwise dominate. Limitations/biases: (i) M_t is a surprise accumulation, not a match-win probability, so its absolute scale is not calibrated to win chances; (ii) the high-stakes flag is a coarse proxy for pressure (40/AD or break point) and does not capture set-point/match-point explicitly; (iii) the alpha horizon is a modeling choice that trades sensitivity against stability, and set-4 (a 6-3 but swing-heavy set) yields only a weak +0.32 signal, showing the index under-weights mid-set reversals. Extended to all 31 matches the same pipeline runs cleanly (average 27 sign-flips/match), confirming the metric is not tuned to one match.

## Subtask 2: Subtask B. Assess the coach's claim that momentum does not play a role and that swings in play and runs of success are p

### Problem

Subtask B. Assess the coach's claim that momentum does not play a role and that swings in play and runs of success are purely random. Use the model/metric to test whether consecutive point-wins carry memory (non-independence) beyond what the serve structure already implies.

### Analysis

Assumptions: the null 'random' model is a per-point independent process whose only structure is the state-conditioned fair probability (same p_srv(state) as Subtask A), i.e. no point depends on the previous points. Any systematic departure from this null — longer runs than chance, or serial correlation in the winner sequence — is evidence against pure randomness. Method: for each match, (a) compare the observed distribution of consecutive point-wins (max run, mean run) against 2000 i.i.d. simulations drawn with the same per-point probabilities; (b) compute the lag-1 to lag-5 autocorrelation of the binary player-1-win sequence. Sound because it isolates *memory* from the dominant serve effect: conditioning on the state baseline means a 'hot streak' can only show up as extra run length or serial correlation, which is exactly the coach's randomness claim made testable.

### Modeling Process

Null model: point wins x_t in {1,2} independent across t, with P(player 1 wins point t)=p1_base(t) from the state baseline of Subtask A. Test statistics per match: (1) max run of consecutive player-1 wins, R_max, and its mean; (2) lag-k autocorrelation r_k = corr(x_{t},x_{t+k}) for k=1..5. Reference: i.i.d. simulation with identical per-point p1_base(t), 2000 replicates, recording max run. A match contradicts the randomness claim if R_max exceeds the simulated max or if |r_1| is materially above 0 (with a small sample the practical benchmark is |r_1|>0.1). Aggregate across the 31 matches.

### Outcome Analysis

Results across all 31 matches (7284 points): observed max run of consecutive wins averages 6.9 points (single-match maximum 13), whereas the i.i.d. null with the same serve structure produces a mean max run of 18.5 — the observed runs are *shorter* than pure randomness with that serve advantage. Mean run length is 2.19 points. Critically, the lag-1 autocorrelation of player-1 wins averages 0.0615 across matches, ranging from -0.057 to +0.206, and **zero of the 31 matches** has |lag-1 autocorrelation| above 0.1. Consecutive point outcomes are therefore statistically indistinguishable from the independent, serve-conditioned null. Conclusion: at the *point* level the coach is essentially correct — there is no measurable 'hot hand' or momentum memory in who wins the next point; runs look dramatic but are consistent with randomness plus the dominant serve effect. The momentum identified in Subtask A operates at a coarser (game/set, ~several-minute) horizon as a *state-dependent shift in play*, not as point-to-point dependence. Caveat/bias: the negative side (observed max runs below simulated) is expected because the serve alternates and the state baseline is strong; the test is most sensitive to *positive* serial dependence (streaks), which is the form 'momentum' would take, and finds none at point level.

## Subtask 3: Subtask C. Build a model that predicts when the flow of play is about to swing from favoring one player to the other; id

### Problem

Subtask C. Build a model that predicts when the flow of play is about to swing from favoring one player to the other; identify the most related factors; advise a player entering a new match against a different opponent; and test the model on other matches to gauge generalizability, including where it performs poorly and what to add.

### Analysis

Assumptions: (1) A 'swing' is a change of the dominant player that *persists* at least one game-length (>=6 points), not a blip — matching the near-term, actionable horizon a coach can act on. (2) The leading indicators are state-dependent and role-specific: for the player in danger who is *serving*, a drop in first-serve-in is the earliest signal; for the player in danger who is *returning*, a jump in unforced errors is the signal; short-rally loss is a symptom, not an independent driver, and is excluded. (3) The decision context is a changeover: the alert must be right clearly more often than not, so the model is read at the operating point where the false-alarm rate is at most one third. Method: per-point features (trailing 8-point windows, strictly before the point to avoid leakage) plus the current M_t and z_t; a regularized logistic model maps features at time t to the probability that a real swing starts within H=20 points; trained on all matches except the featured one and tested out-of-sample on the featured match, with a leave-one-match-out pooled estimate for generalizability. Sound because it is a proper supervised, out-of-sample, imbalanced-class problem whose threshold is tied to the stated decision criterion rather than to raw accuracy.

### Modeling Process

Features at point t (trailing window w=8, strictly prior points; NaNs filled by per-match median): fsin = server's first-serve-in rate (fraction of first serves that held); ufe_srv = UFE rate of the serving player; ufe_ret = UFE rate of the returning player; winrate = server's point-win rate; break_pt, high_stakes (state flags); server2 (which player serves); M_t (Subtask A flow); z_t (current surprise). Label y_t=1 if a real swing (a dominance run of length >= hold=6 by the other player) starts within H=20 points after t. Model: L2 logistic regression, C=0.1, class-weighted for imbalance, features standardized. Decision rule: raise the alert when P(swing) >= threshold with the threshold chosen so the false-alarm rate <= 1/3. Parameter table (empirical/structural, from the task dataset and the interaction exchanges): window w=8 points, interval [5,10], source: feature sweep; swing persistence hold=6 points (~one game), interval [4,8], source: exchange-3 'next 2-4 games, must persist' criterion; alert horizon H=20 points (~2-4 games), interval [10,30], source: exchange-3 'next 2-4 games (10-20 min)' criterion; alert threshold false-alarm <= 1/3 (precision >= ~0.5), source: exchange-3 'ignore a warning that fires more than about a third of the time' criterion. All rate features are computed from the dataset; no external numeric parameters are introduced.

### Outcome Analysis

Holdout on the featured match 1701 (334 test points, base rate of 'a swing ahead' = 0.533): at the decision threshold (false-alarm <= 1/3), precision = 0.692, recall = 0.618, with 159 alerts; the model beats the base rate by ~0.16 in precision and stays under the one-third false-alarm ceiling. Out-of-sample generalizability, leave-one-match-out across the other 30 matches (base rate 0.537): precision = 0.556 at the same operating point, false-alarm = 0.444 — a positive but modest lift over base rate, meaning the signal generalizes but weakly outside the featured match. Coefficient signs identify the most related factors: the UFE-rate features carry the largest weights (ufe_srv and ufe_ret, negative, i.e. an elevated error rate for the player in danger precedes the swing), followed by the current momentum M_t and the break-point flag — consistent with the expert's ranking (serve-rhythm and error-rate are the leading indicators). Advice for a player entering a new match against a different opponent: (i) the point-to-point 'hot hand' is not real (Subtask B), so do not assume a run will continue; (ii) the actionable early warning is role-specific — if you are serving and your first-serve-in has dropped over the last two service games, commit to a target and accept the second serve; if you are returning and your error rate is climbing, pull your aggression back; (iii) treat these as next-2-to-4-game cues, not match-level prophecies. Where the model performs poorly: the out-of-fold lift is small, and alerts fire most often when the match is already close, so it under-performs in lopsided, low-variance stretches and late in a match where little remains to swing. Factors to add in future work: (a) serve placement and speed (speed_mph, serve_width/depth) and aces/double-faults as more granular serve-quality signals; (b) player identity and temperament (fragile-confidence players show stronger drift, per exchange 1); (c) surface and tournament context and match-elapsed fatigues; (d) set/game scoreline as explicit high-stakes context. Generalizability: the metric and the indicator structure are sport- and surface-agnostic in form (any alternating-serve, point-based contest — e.g. table tennis — has a server advantage and a state-dependent drift), so the *framework* transfers to Women's matches, other surfaces, and table tennis; the *calibrated probabilities and coefficients* would need re-estimation on each new population because the serve advantage and error baselines differ.
