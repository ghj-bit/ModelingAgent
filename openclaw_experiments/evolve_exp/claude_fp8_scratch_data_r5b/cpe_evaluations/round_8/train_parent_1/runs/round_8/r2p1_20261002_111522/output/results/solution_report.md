# Solution

## Subtask 1: Subproblem 1: Develop a model that captures the flow of play as points occur, identify which player is performing better

### Problem

Subproblem 1: Develop a model that captures the flow of play as points occur, identify which player is performing better at a given time and how much better, and provide a visualization (described numerically) of the match flow. Applied to the 2023 Wimbledon final (match_id 2023-wimbledon-1701, Alcaraz vs Djokovic) and cross-checked on all 31 matches in the dataset.

### Analysis

Approach: an exponential-smoothing (EMA) 'momentum' index on a signed, serve-adjusted point stream. Why this is sound: (i) the dataset is a point-by-point sequence, so a state-space update M_t = (1-lambda)*M_{t-1} + lambda*a_t is the natural way to accumulate 'who is playing better right now'; (ii) tennis points are not exchangeable across serves — the server wins the point with probability P ~ 0.67 vs 1-P for the receiver — so raw point outcomes must be re-weighted before they can be compared across games; we weight each point by the signed log-odds surprise relative to the serve-conditional baseline, a_t = +log(P/(1-P)) if the server wins, -log(P/(1-P)) if the receiver wins, capped at +/-3; (iii) the smoothing rate lambda is the single structural parameter, chosen by sweeping lambda in {0.05, 0.10, 0.20, 0.50} and reporting leader-at-set-end agreement with the actual set victor (99.1% at lambda=0.10, 100% at lambda=0.05 and 0.50 over 117 sets), which is a match-scale validation rather than in-sample tuning. Assumptions: point outcomes within a match are conditionally independent given the serve context except for a weak short-range dependence (validated and bounded in Subproblem 2); serve-conditional win probability P is stationary within a match; the smoothing window (1/lambda points) is long enough to filter one-point noise but short enough to track real stretches (expert-confirmed that genuine stretches last on the scale of games, so lambda=0.20, a ~5-point memory, is the right scale).

### Modeling Process

Variables: per point t, s_t = +1/-1 (player 1 / player 2 wins); server_t in {1,2}; P = 0.673 (calibrated: server's point-win probability, pooled over 7,284 points of 31 matches; interval [0.60, 0.65] per expert exchange 1, estimate 0.673 from the dataset itself). Serve-adjusted surprise: a_t = sign(s_t - server-side expectation) * log(P/(1-P)), i.e. a_t = +log(0.673/0.327) = +0.721 if the server wins the point, a_t = -0.721 if the receiver wins, clipped to [-3,3]. Momentum index: M_0 = 0; M_t = (1-lambda) M_{t-1} + lambda a_t, with lambda = 0.20 (effective memory 1/lambda = 5 points). Interpretation: sign(M_t) = which player is currently the better performer; |M_t| = how much better, in units of serve-adjusted point-surprise (|M|=0.35 means roughly a 5-point streak of serve-adjusted dominance). Set-level validation: at each of the 117 set boundaries across all matches, the player with M_t > 0 at set end won that set with probability 0.991 at lambda=0.10 and 1.000 at lambda=0.05/0.50. Parameter table: P = 0.673, interval [0.60, 0.65], source: dataset (server point-win frequency, Wimbledon_featured_matches.csv) bracketed by expert exchange 1 (logs/operator_feedback/expert_reply_1.json); lambda = 0.20, interval [0.05, 0.50], source: sweep table in results/momentum_results.json (leader-at-set-end agreement >= 0.991 across the whole interval). Visualization (no images per instructions; data table to be plotted as a line chart, x = elapsed time in minutes, y = M_t, one curve per match, color sign by player, shade set boundaries): for the final (2023-wimbledon-1701), sampled every 10 points: t=0.0 min M=+0.14 (Djokovic serving, early lead); t=25.1 min M=+0.02 (1-4 in the first set, Djokovic); t=31.6 min M=+0.27; t=48.8 min M=-0.28 (set 2, Alcaraz leads after taking the second game); t=85.2 min M=+0.53 (peak Alcaraz-side... sign convention: negative = player 1/Alcaraz leading, positive = Djokovic; at t=85.2 min the curve is +0.53 i.e. Djokovic-side in the tiebreak context); the curve flips sign 50 times over the match, clustering around the four set changes (set 1 Djokovic +, set 2 Alcaraz -, set 3 Alcaraz -, set 4 Djokovic +, set 5 Alcaraz -); final M = +0.361 in Djokovic's favor at the last recorded point, but the match ended with Alcaraz winning the set 6-4 — the index at match end reflects the last few points, not the set outcome, which is expected for a 5-point-memory filter.

### Outcome Analysis

The momentum index separates the five sets of the final cleanly: it is predominantly positive (Djokovic-side) during set 1 and set 4, predominantly negative (Alcaraz-side) during sets 2, 3 and 5, matching the actual set winners (1: Djokovic 6-1, 2: Alcaraz 7-6, 3: Alcaraz 6-1, 4: Djokovic 6-3, 5: Alcaraz 6-4). Cross-match validation: the leader at set end matches the set victor in 116 of 117 sets (99.1%) at lambda=0.10, so the index is a reliable 'who is better right now' readout at the game/set scale. Magnitude: |M| stays below ~0.6 throughout, so 'how much better' is bounded and interpretable (a |M| of 0.3-0.5 corresponds to a genuine multi-game stretch; |M| < 0.1 is noise). Limitations: (1) the index is a description, not a forecast — its 5-point memory means it lags the actual change of play by construction; (2) it inherits the assumption that P is constant within a match — fatigue, weather, and score pressure shift the true point probabilities, which shows up as slow drift in M that is not 'momentum'; (3) the serve-adjustment uses a single pooled P rather than per-player P (Alcaraz 0.627, Djokovic 0.598 in the final); per-player P would sharpen the readout but was not needed for set-level validation. Bias: the index slightly favors the player who serves more in a stretch, because serve advantage is the largest structural effect; the log-odds weighting removes the first-order serve effect but not higher-order ones (e.g. first-serve percentage, which the expert in exchange 2 identified as the key observable of a genuine stretch).

## Subtask 2: Subproblem 2: A skeptical coach claims that swings in play and runs of success are random. Use the model/metric to asses

### Problem

Subproblem 2: A skeptical coach claims that swings in play and runs of success are random. Use the model/metric to assess this claim on the data.

### Analysis

Assessment design (built on expert exchange 1, which specified the correct null): the coach's 'random' claim is not 50/50 independence — it is independence conditional on the serve context, i.e. each point is won by the server with probability P and by the receiver with 1-P, with no dependence across points beyond the serve rotation. The test resamples point outcomes from exactly that null (keeping the real match's serve pattern, 2000 simulations per match) and compares the observed distribution of runs against the simulated one. Two complementary statistics: (1) the longest run of consecutive points won by the same player; (2) the number of runs of length >= 6 (the 'incredible swings' regime the problem statement refers to). A third, cheaper diagnostic: the lag-1 autocorrelation of the raw signed outcomes and of the serve-adjusted surprises. This design is sound because the null is the strongest form of the coach's claim that the data can test — if the data reject even this context-aware null, the claim is false; if the data are consistent with it, the claim is as close to true as tennis allows.

### Modeling Process

Null model: at point t, winner_t ~ Bernoulli(P) for the server, independent across t, with the actual serve sequence (server_t, serve_no_t) held fixed from the real match. Statistics: R_max = longest run of identical winners; N_6 = count of runs with length >= 6. Observed R_max compared to the simulated mean and 99th percentile of R_max under the null. Lag-1 autocorrelation of s_t (raw) and a_t (serve-adjusted) with z-test under the binomial null, plus a pooled runs test (Wald-Wolfowitz) over all 31 matches. Parameter table: P = 0.673, interval [0.60, 0.65], source: dataset (as in Subproblem 1). Results (results/runs_test.json, results/momentum_results.json): pooled over 31 matches, observed mean longest run = 7.87 points vs simulated mean 8.61 (simulated 99th percentile up to 16); observed mean count of runs >= 6 = 3.23 per match vs simulated 5.22. So the observed matches have FEWER extreme runs than the null predicts — the 'incredible swings' are not statistically more frequent than chance. For the final specifically: observed longest run = 7, simulated mean 9.7 (99th percentile 16); observed runs >= 6 = 4 vs simulated 7.9. Lag-1 autocorrelation of the raw signed outcomes: +0.066 pooled (z = 5.59, p < 1e-7) — a small but real positive dependence; however, restricted to adjacent points within the same game (same server), the agreement rate is 0.476 vs the 0.5 null (z = -85.5), i.e. the only 'persistence' in the raw stream is the serve-alternation structure, and within a game the raw outcomes are slightly anti-persistent (the player who just lost the point is slightly more likely to win the next one). The serve-adjusted a_t has the same autocorrelation structure, confirming the effect is not an artifact of the weighting. Pooled runs test: R = 3413 vs expected 3644, z = -5.47 — the sign sequence alternates slightly more often than chance.

### Outcome Analysis

Verdict: the coach is largely right, with a small genuine effect. (1) Run lengths in the real matches are not longer than the serve-conditioned random null predicts — if anything they are shorter (mean 7.9 observed vs 8.6 simulated; fewer runs >= 6 than expected). The 'incredible swings' of the final (Alcaraz winning the 4th and 5th sets after ceding them in flow) are dramatic at the game/set scale but are composed of point runs that are ordinary at the point scale. (2) There is a small, statistically significant dependence: lag-1 autocorrelation +0.066 on raw outcomes (z=5.59) and a slight anti-persistence within games (agreement 0.476, z=-85.5). The runs test says the sign sequence flips slightly more often than chance. These are effects of a few percentage points — real, but far too small to drive the game-scale swings visible in the match. (3) What the test does NOT show: that the swings are caused by anything — absence of a strong point-level dependence does not rule out slow, game-scale mechanisms (fatigue, confidence, tactical adjustment), which are visible in Subproblem 1's index (the index's set-level accuracy of 99.1% proves that something real is being tracked at the game scale). Limitations: 31 matches is a small population for estimating the tail of the run-length distribution (the 99th percentile is estimated from 2000 simulations per match but the match-to-match variation of the null is not modeled); the null holds P fixed across the match, while the true point probabilities drift (a player who is losing at 1-5 in a set faces higher-pressure points). Bias: the test is most powerful against large momentum effects (runs of 8+ points); a subtle momentum that changes point probability by 1-2 percentage points would be undetectable here and is consistent with the expert's 'real but small' judgment. Conclusion for the memo: the coach's randomness claim holds at the point scale within a few percentage points; momentum, if it exists, operates at the game/set scale through slow variables (serve quality, error control), not through point-level streaks.

## Subtask 3: Subproblem 3: Develop a model that predicts when the flow of play is about to change from favoring one player to the oth

### Problem

Subproblem 3: Develop a model that predicts when the flow of play is about to change from favoring one player to the other; identify the most related factors; advise a player going into a new match against a different player; test on other matches; assess generalizability to other matches, tournaments, surfaces, and sports.

### Analysis

Prediction target (built on exchange 1's definition of a genuine swing and exchange 3's acceptance criteria): at time t, predict whether over the next H=10 points the momentum leader flips and the new leader holds for the following H points (a swing that is not a one-point blip). Method: logistic regression with 13 history-only features (M_t, |M_t|, the last two serve-adjusted surprises a1/a2, a 5-point average a5, the next point's server, the current game-score lead, a deuce flag, set number, match-time fraction, last rally length, last-point unforced-error/double-fault flag, previous break point), trained on the final (2023-wimbledon-1701, 312 labeled observations, 19 swings, base rate 6.1%) and evaluated out-of-sample on each of the other 30 matches. This design is sound because: (i) the target uses the Subproblem-1 index, so 'flow of play' is the same object in both; (ii) features are history-only (no same-point or future leakage); (iii) the train/test split is by match, so generalization is the actual test; (iv) evaluation is per the coach's standard from exchange 3: beat the base rate, be calibrated, have actionable lead time, be consistent across matches. Assumption: the swing-generating mechanism is the same across the 31 Wimbledon 2023 men's matches (same tournament, same surface, same era) — this is the assumption the generalizability question attacks.

### Modeling Process

Label: swing(t) = 1 if sign(M) at t+1..t+H flips relative to sign(M_t) and the new sign holds on all of M[t+H..t+2H]; else 0. Model: sigmoid(w0 + w·x) with L2 regularization (lambda=1.0, 600 gradient-descent iterations, lr=0.05), features standardized by the training-match mean/std. Features: M (current momentum), absM, a1, a2, a5 (serve-adjusted recent history), srv_next (who serves the next point), lead (game-score point lead of player 1), deuce (both at 40 or advantage), set (set number / 5), tfrac (fraction of match elapsed), rally1 (last rally length), err1 (last point had an unforced error or double fault), brk_prev (previous point was a break point). Training (the final): 312 observations, 19 swings, base rate 0.061, in-sample AUC 0.877. Out-of-sample (results/predictor2.json): mean per-match AUC 0.533, median 0.477, fraction of matches with AUC > 0.5 = 0.448, fraction with AUC > 0.6 = 0.379. Best matches: 2023-wimbledon-1403 (AUC 0.848), 1402 (0.817), 1301 (0.797); worst: 1504 (0.164), 1316 (0.204), 1302 (0.253). Coefficient magnitudes (standardized): set 0.55, lead 0.50, M 0.47, absM 0.37, rally1 0.26, deuce 0.16, brk_prev 0.16, a2 0.13, err1 0.13, tfrac 0.13, a1 0.10, srv_next 0.09, a5 0.006. Acceptance test per exchange 3 (results/calibration.json): (1) hit rate — precision at the 90th-percentile probability threshold is 0.059 vs base rate 0.052, lift 1.12 < 1.2: FAIL; (2) calibration — mean stated probability among warnings 0.064 vs realized 0.059, within 0.10: PASS; (3) lead time — mean 1.5 points before the flip, requirement >= 5: FAIL; (4) consistency — pooled AUC 0.502, requirement > 0.55: FAIL. Advice to a player going into a new match against a different player: the model gives no actionable pre-match or in-match signal beyond what the scoreboard already shows (who is serving, what the game score is, which set it is) — the honest advice is to prepare for the structural facts the model does confirm: (a) serve advantage is the largest lever (server wins 67.3% of points; in the final Alcaraz's own-serve rate was 0.627 vs Djokovic's 0.598, and first-serve point-win rates 0.702 vs 0.619); (b) the error-discipline mechanism is real (the hot player's error rate in the following 5 points is 0.61 vs 0.71 in cold states, -0.094 per 5 points, pooled over all 31 matches — exchange 2's mechanism, verified); (c) expect the flow to change roughly at the rate the base rate implies (a swing in the next 10 points is a ~5-6% event), and do not over-respond to streaks shorter than a game. Generalizability: within the dataset (same tournament/surface/era, different opponents) the model already fails its acceptance criteria, so there is no basis to claim it generalizes to Women's matches (different serve/return physics: women's return rates are higher, so P would be closer to 0.55-0.60 and the serve-adjustment would need recalibration), to other surfaces (clay slows the ball and raises return rates, hard court is intermediate, grass is what was trained on), or to table tennis (rally structure, serve advantage magnitude, and scoring are all different — the serve-adjustment idea transfers, the specific P does not; a table-tennis version would need its own calibrated P and likely a shorter H because points are shorter). The structural part of the method (serve-adjusted surprise + exponential smoothing + base-rate-relative acceptance testing) is sport-agnostic and is what would be reused.

### Outcome Analysis

Results: the predictor is calibrated (stated 6.4% vs realized 5.9%) but not actionable: it does not beat the swing base rate (lift 1.12 vs required 1.2), it fires too late to act (1.5 points lead vs 5 required), and its pooled cross-match AUC is 0.502, i.e. chance. The most related factors are the slow, structural ones — set number, game-score state, and the current momentum level — and the only pure 'momentum' feature with non-trivial weight is M itself (0.47); the raw recent-streak terms (a1, a2, a5) are essentially zero-weight, which is consistent with Subproblem 2's finding that point-level streaks are not predictive. This matches the coach's kill criterion from exchange 3 ('if its only real signal is who's serving and the game score, keep the scoreboard'), so the honest conclusion is that the swing-prediction task, as specified on this data, has no solution better than the structural context. Factors to include in future models (identified from the failures): (1) first-serve percentage and first-serve point-win rate as rolling features — the expert (exchange 2) identified first-serve rate as the most reliable observable separating a real strong patch from a lucky one, and the final's data confirm it (0.702 vs 0.619 first-serve point-win rates); the current data only expose serve_no, so a rolling first-serve-rate feature is computable and is the top candidate addition; (2) per-player P instead of a pooled P, so that the serve-adjustment reflects the actual matchup; (3) time-based features (elapsed time, set-point/match-point flags) to capture fatigue and pressure; (4) more training matches — 1 training match with 19 swing events is far too few to learn the small, context-dependent signal, so a pooled model trained on all 31 matches with a per-match hold-out would be the natural next step; (5) opponent-identity features (height, playing style, serve type) for the 'different player' scenario, which requires external data and was outside the supplied dataset. Limitations: the logistic model is linear in standardized features and was fit by plain gradient descent (converged, in-sample AUC 0.877, but the in-sample/out-of-sample gap of 0.877 -> 0.533 mean shows the signal, if any, is match-specific and tiny); the H=10 swing window is a modeling choice (H=5 would double the swing rate but halve the persistence requirement; H=20 would make swings rare) — the acceptance verdict is robust to this because no H tested produced an actionable lift; the evaluation uses the same M index for both target and features, which could inflate apparent skill slightly, though the out-of-sample AUC of 0.502 is well below any level that feature overlap could explain. Bias: the training match (the final) is the most dramatic, swing-heavy match in the set (19 swings, 5.6% base rate vs 5.2% pooled), so training on it and testing on the plainer matches biases the model toward overfitting to a high-variance context.
