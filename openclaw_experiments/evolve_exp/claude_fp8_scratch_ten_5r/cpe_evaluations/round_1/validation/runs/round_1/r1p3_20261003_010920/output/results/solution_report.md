## Subtask 1: Requirement 1: Build a model and algorithm that prioritizes all 83 office workers by likelihood of being part of the con

### Problem

Requirement 1: Build a model and algorithm that prioritizes all 83 office workers by likelihood of being part of the conspiracy, explain the model and metrics, and determine whether any of the three senior managers (Jerome, Delores, Gretchen) are involved. Inputs: 7 known conspirators (Jean, Alex, Elsie, Paul, Ulf, Yao, Harvey), 8 known non-conspirators (Darlene, Tran, Jia, Ellin, Gard, Chris, Paige, Este), 3 known suspicious topics (7, 11, 13), and the message network (Messages.csv). Output: a ranked priority list with a clear discriminate line separating likely conspirators from non-conspirators, plus a leader nomination.

### Analysis

Assumptions: (1) Conspirators form a dense, tightly-knit subgroup with a few bridging ties, not a random spread (EX5). (2) The detectable signal is in topic composition and structural position, not raw message volume — conspirators keep routine volume normal and shift traffic onto covert 'innocent-looking' topics (EX3, EX6). (3) Conspirators use normal, open channels; there is no channel-absence or off-channel anomaly to detect (EX6). (4) Leaders are insulated organizers who show up as low-degree but high-betweenness broker nodes, and are caught last (EX2, EX4). (5) Senior managers who are involved appear sparsely and indirectly, judged by structural position and topic mix rather than message count (EX9). (6) The total conspirator group is a small minority, roughly 5-15 of 83, so the priority list should be read as a short, sharply ranked, high-precision list with a clear cutoff (EX7, EX8). (7) Names are duplicated in the dataset (Gretchen, Jerome, Neal, Elsie, Beth each appear at two node IDs); a named label is therefore applied to every node bearing that name, and the model is run on node IDs so the ranking is unambiguous. Method choice: a weighted message network scored by a combination of (a) covert-topic participation, (b) eigenvector centrality (embedding in a well-connected core), and (c) local clustering (dense subgroup). Raw degree is deliberately excluded from the membership score because, per EX3/EX6, high volume is not a conspirator signal. A separate leader score rewards betweenness (brokerage) gated on covert participation. This method is sound because it targets the structural and topical signatures that expert judgment identifies as the actual evidence of a scheme, and it is validated against the 7 known conspirators and 8 known non-conspirators.

### Modeling Process

Data cleaning: 535 raw rows -> dropped 135 fully blank trailing rows, dropped 2 self-loops (node cannot message itself), kept 398 messages (12 true duplicate message records retained as distinct messages; 47 messages carry 2+ topics). Node set = 83 (IDs 0-82). Graph construction: undirected weighted graph G over 83 nodes. Each message (s,e, topics) contributes edge weight w = n_topics * topic_weight + suspicious_weight if any topic is in the suspicious set S, else n_topics * topic_weight. topic_weight=1.0, suspicious_weight=2.0, S={7,11,13}. Per-node features: deg (weighted degree), betw (betweenness centrality, unweighted), eig (eigenvector centrality), clus (local clustering coefficient). Covert-fraction susp_frac(i) = (sum of suspicious-weight on incident edges) / (total weighted degree), the fraction of a node's traffic that is covert. All normalized min-max. CONSPIRATOR MEMBERSHIP SCORE: score(i) = struct_weight * susp_frac(i) + eig_weight * eig(i) + clus_weight * clus(i), with struct_weight=1.0, eig_weight=0.6, clus_weight=0.4. Raw degree is NOT a term (EX3/EX6). LEADER/BROKER SCORE: leader_score(i) = 1.2 * leader_weight * betw(i) * [susp_frac(i)>0] + 0.4 * leader_deg_penalty * (1 - deg_norm(i)) * [betw(i)>0.1] + 0.4 * struct_weight * susp_frac(i), with leader_weight=1.0, leader_deg_penalty=0.6. The betweenness term is gated on covert participation so isolated nodes with pure covert traffic (no brokerage role) are not over-weighted (EX2/EX4). DISCRIMINATE LINE: flag(i)=HIGH iff score(i) >= threshold=1.055 (top 17 nodes, ~20% of 83, bracketing the 5-15 expected-conspirator range with a precision-first top-5). LEADER SHORTLIST: leader_score(i) >= 0.90 -> {Franklin, Sherri}. Parameter provenance: suspicious topics {7,11,13} = task statement; topic_weight=1.0, suspicious_weight=2.0 (swept 1-4, ranking invariant, logs/sweep1.log); struct/eig/clus weights 1.0/0.6/0.4 (swept, P@5=0.80 whenever struct>=1.0 and eig<=0.6, logs/sweep2.log); leader threshold 0.90 and membership threshold 1.055 set from EX7/EX8 (short minority, sharply ranked list) and the observed score gap; leader prior (mid/senior managers, organizer often mid-level) from EX1; leader=high betweenness low degree from EX2; membership=topic mix not volume from EX3; broker-over-degree from EX4; dense core from EX5; open channel unusual content from EX6; ~5-15 total conspirators from EX7; short ranked list + cutoff from EX8; senior-manager pattern from EX9.

### Problem

Requirement 3: Explain how semantic network analysis and text analysis of the message content and context (if the original messages could be obtained) would empower better models and categorizations of the office personnel. Did we use any of these capabilities on the topic descriptions in Topics.xls to enhance the model?

### Analysis

The current model is deliberately conservative: it sees only node pairs and topic codes, not transcripts. Requirement 3 asks how the full text would improve the model. Two AI/NLP capabilities are relevant. (1) Semantic network analysis: build a graph of concepts/terms from the messages and measure how covert-related concepts (embezzlement, off-line windows, system flaws, private meetings) co-occur and bridge to benign concepts, identifying which nodes' language is 'semantically' aligned with the conspiracy even when topic codes differ. (2) Text analysis: term-frequency / topic-model (LDA) extraction, sentiment and register detection, and detection of coded or discretion-seeking language. Both turn the opaque topic codes into measurable content features. We did use a limited, qualitative form of this on Topics.xls: the topic descriptions were read to justify the suspicious-topic set {7,11,13} and to characterize what each covert topic means (Topic 7 = private evening meeting at Paul's house with 'be discreet' reminders and Spanish code words; Topic 11 = flaws in the accounting, credit-card, and auditing packages; Topic 13 = the plan to keep Paige, Ellin, and Chris off-line for a significant period). That reading is what allows the model to treat these three topics as covert rather than as a data-driven guess, and it is where the 'be discreet' / coded-language cue enters (EX10: a weak-to-moderate modifier, absorbed through topic coding, not a standalone feature).

### Modeling Process

If transcripts were available, the model would add a content layer on top of the network layer. Concretely: (a) vectorize each message (TF-IDF or embeddings) and fit a topic model; the probability mass of a node's messages on the covert topics (7,11,13 and, in Req 2, 1) replaces the binary suspicious-topic flag with a graded covert-content score c(i) in [0,1]. (b) Build a semantic term graph (term-term co-occurrence within and across messages); compute, per node, the semantic distance between that node's message language and the covert-concept centroid, giving a second independent covert-alignment feature. (c) Detect coded/discretion language (e.g., 'be discreet', 'keep quiet', Spanish code words) as a low-weight amplifier a(i) that multiplies, never stands in for, the structural score (per EX10: weak-to-moderate, modifier-only). (d) Add directed, temporal features: message burstiness around decision points and reciprocity asymmetry (EX3: pattern shift, not volume spike), giving features for tightness of the core and insulation of the organizer. The membership score would become score(i) = w1*c(i) + w2*semantic_align(i) + w3*susp_frac(i) + w4*eig(i) + w5*clus(i) + w6*a(i), with the network features retained so the model still works when only topic codes exist. The leader score would additionally use the semantic graph to confirm that a broker's few messages are the ones that carry covert content (the organizer's high-value, low-count pattern).

### Outcome Analysis

The added content layer would improve the model in three specific ways: (1) it removes the binary limit of 'is this topic suspicious' and grades covert content, catching conspirators who split their covert talk across benign-coded topics; (2) the semantic term graph is independent of the investigator's topic coding, so it would surface covert clusters the human coders missed (and confirm or refute the 7/11/13 choices); (3) the coded-language detector would let the 'be discreet' cue (EX10) be applied where it belongs — as an amplifier inside an already-suspicious cluster — rather than being averaged into a single topic code. It would also sharpen the leader read: an organizer's handful of messages can be checked for covert semantic content, directly testing the insulated-organizer hypothesis (EX2/EX4/EX9). Limitations: text analysis adds a dependence on the quality of the transcripts and on the topic model; it is expensive at the 'thousands of people, tens of thousands of messages, millions of words' scale the supervisor targets, so the network model remains the scalable core and the text layer is the refinement. Yes, a qualitative form of the capability was used on Topics.xls (justifying the suspicious-topic set and reading the 'be discreet'/coded-language cue), but no full semantic network or text model was run because the transcripts are not supplied.

### Problem

Requirement 4: Write a detailed report (<=20 pages) for the DA, clearly stating assumptions and methodology, that includes (a) a discussion of how more thorough network, semantic, and text analyses of the message contents could help the model and recommendations, and (b) an explanation of the network modeling techniques used, why, and how they generalize to identify, prioritize, and categorize similar nodes in a network database of any type — with the specific example of finding infected or diseased cells in a biological network where nodes have various image/chemical data indicating infection probabilities and some infected nodes are already identified.

### Analysis

This requirement is the generalization and methodology-report component. The core claim is that the conspiracy model is an instance of a general supervised-informed network-scoring problem: given a graph with node/edge features, a small set of positively and negatively labeled nodes, and a known set of 'suspicious' edge types, score all nodes by likelihood of the hidden class and a separate score for the organizing/broking role. That formulation is domain-agnostic, so the same machinery transfers to biological, social, financial, or infrastructure networks. The biological-network example in the prompt is exactly this structure: nodes=cells, node features=image/chemical infection-probability data, edge features=interaction/adjacency, labeled nodes=some confirmed-infected and some confirmed-healthy cells, suspicious edges=the interaction types associated with disease spread. The methodology and assumptions are stated so a DA (or a biologist) can audit every step.

### Modeling Process

General methodology (network, semantic, text): STEP 1 Build the network — nodes are entities, edges are interactions, edge weights accumulate over messages/interactions, and a known set of edge types is flagged as 'suspicious' (in crime: topics 7/11/13; in biology: interaction types correlated with disease). STEP 2 Compute per-node features — (a) fraction of a node's edge weight that is on suspicious edges (the covert/infection-adjacency fraction, the analogue of susp_frac), (b) centrality features (eigenvector for embeddedness in a well-connected core; betweenness for brokerage; local clustering for dense-subgroup membership; degree used only for the broker/organizer test, never as the primary signal), and (c) any node-level measured features (in biology the image/chemical infection-probability data are exactly this — they slot in as an additional weighted feature just as a transcript's covert-content score would). STEP 3 Score membership — a weighted sum of the suspicious-edge fraction, embeddedness, clustering, and node-level measured features, with raw degree excluded as a primary signal (the infected-cell and conspirator analogues both hide inside normal-looking, well-connected neighborhoods rather than being the loudest nodes). STEP 4 Score the organizer/spread-hub role — a separate betweenness-gated score that identifies the few nodes bridging otherwise-separate clusters (the conspiracy leader; in biology the hub cell or the cell whose position in the interaction graph makes it the likely origin/spread node). STEP 5 Draw the discriminate line — a threshold on the membership score that separates a short, high-precision high-risk tier from the rest, sized to the expected minority prevalence (crime: ~5-15 of 83; biology: the expected fraction of infected cells). STEP 6 Validate against the labeled nodes (known conspirators / known infected cells) by precision@k and separation, and sweep the feature weights to confirm robustness. How it helps the model and recommendations: (a) more thorough network analysis — community detection (Louvain/Infomap) to isolate the dense core and its bridge nodes, k-core/lineage decomposition to rank how deeply embedded each node is, and temporal/directed analysis to catch the pattern-shift (EX3) rather than volume; recommendation: report both the membership tier and the broker hub, and the community each falls in, so investigators/biologists see the group structure, not just a list. (b) Semantic analysis — build the concept/co-occurrence graph from the raw data and measure each node's distance to the suspicious-concept centroid, giving an independent, coder-free confirmation of the flagged edges; recommendation: use it to audit the human-chosen suspicious set and to find missed covert clusters. (c) Text analysis — topic modeling and coded/discretion-language detection to grade covert content and to amplify (never replace) the structural score (EX10); recommendation: treat coded-language cues as a low-weight multiplier applied only inside a suspicious community. Scale: at millions of words / thousands of nodes, the network model is the scalable core (centrality and community detection are near-linear) and the semantic/text layers are applied to the flagged high-tier nodes only, keeping cost bounded.

### Outcome Analysis

Biological-network example (infected/diseased cells): map the crime model directly. Nodes = cells with image/chemical features giving an infection probability p_inf(i) (this is the node-level measured feature that plays the role the message content would play in crime). Edges = cell-cell interaction/adjacency with type; a known set of interaction types is flagged as disease-associated (the analogue of suspicious topics 7/11/13). Labeled nodes = some confirmed-infected and some confirmed-healthy cells (the analogue of the 7 known conspirators / 8 known non-conspirators). Then: covert-adjacency fraction susp_frac(i) -> the fraction of cell i's interaction weight on disease-associated edges; eigenvector -> embedding in a well-connected diseased core; local clustering -> membership in a dense diseased cluster; the node-level feature -> p_inf(i) added as a weighted term. The membership score ranks cells by infection likelihood; the betweenness-gated leader score identifies the hub cell or the cell bridging healthy and diseased clusters (the likely origin/spread point). The discriminate line is set to the expected infected-cell fraction. Validation is precision@k and separation against the confirmed-infected and confirmed-healthy cells. Why the same method fits: an infected cell, like a conspirator, is typically well-connected and hides among normal-looking neighbors (EX3/EX6 analogues: the 'signal is in composition and structure, not raw volume/degree' principle holds because both diseased and covert cells are embedded in dense cores, not isolated loud outliers), and the disease's 'origin/spread' node, like a conspiracy leader, is a broker between otherwise-separate regions (EX2/EX4 analogue). Caveats and biases: the method inherits the same limitations in both domains — a low-activity infected cell (like Harvey, the low-activity known conspirator) can score low and be missed; the threshold/line is a read for investigation, not a hard count; the suspicious-edge set and the node-level features carry the prior, so their quality bounds the result; and in biology, as in crime, the model flags candidates for confirmation, it does not prove infection/involvement. These caveats are stated so the report is honest about what the method can and cannot conclude.
