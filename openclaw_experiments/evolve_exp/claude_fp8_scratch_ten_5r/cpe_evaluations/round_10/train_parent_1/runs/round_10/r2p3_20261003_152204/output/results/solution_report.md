## Subtask 1: Develop a model that captures the flow of play point-by-point in tennis, identify which player is performing better at a

### Problem

Develop a model that captures the flow of play point-by-point in tennis, identify which player is performing better at any given time and by how much, and provide a data-based depiction of the match flow. Applied to the 2023 Wimbledon final (match 2023-wimbledon-1701, Alcaraz p1 vs Djokovic p2) and all 31 provided matches. The model must account for the serving advantage explicitly.

### Analysis

Assumptions: (1) each point outcome is a Bernoulli trial whose probability is governed by a latent per-player performance state plus the serving advantage; (2) the latent state evolves as a weakly persistent (AR(1)) process driven by observable point events - point wins, first-serve misses, break points faced, unforced errors, double faults - so that the state is reconstructible from the point data alone; (3) the serving advantage is a constant log-odds shift (first vs second serve, plus a server bonus), the same for both players; (4) no player-specific priors are used beyond what the point data reveal, so the model is fully data-driven per match. This structure is sound because it matches the observed dominance pattern in the data (server wins 67.3% of points; 75.4% on first serve vs 53.0% on second serve, 7284 points), it treats momentum as a measurable quantity rather than a narrative, and every parameter is estimable by maximum likelihood from the supplied CSV. Method: per-point latent strengths s1, s2; edge = s1 - s2; point probability P(p1 wins) = sigmoid((edge + cF*(first serve - second serve) + cS*(server1 - server2))/k); strengths follow s_{t+1} = (1-a)*s_t + b*w_t + h*(first_t - 1) + g*bp_t + fu*ue_t - fd*df_t per player. Parameters fitted per match by bounded L-BFGS-B on the negative log-likelihood; 7 parameters per match, no tuning beyond box constraints that encode scale (k in [0.15, 1.5], coefficients in small positive/negative boxes) chosen for identifiability, not performance.

### Modeling Process

Per point t (t = 0..n-1) with outcome w_i in {0,1} for player i: state update s_i,t+1 = (1-a) s_i,t + b w_i,t + h (I[serve_no=1] - 1) + g bp_i,t + fu ue_i,t - fd df_i,t, s_i,0 = 0. Point model: P(p1 wins t) = sigmoid(( (s1,t - s2,t) + cF*(I[serve_no=1]-1) + cS*(2*I[server=1]-1) ) / k). Likelihood L = prod_t p_t^{w1,t} (1-p_t)^{1-w1,t}; parameters theta = (a, b, h, g, fu, fd, k, cF, cS) by MLE with bounds a in [0.001,0.4], b,h in [0,1]/[-1,1], g in [0,1.5], fu,fd in [0,1], k in [0.15,1.5], cF,cS in [-1.5,1.5]. Momentum indicator m_t = (s1,t - s2,t)/k in log-odds units; m_t > 0 means player 1 is the better performer at that moment and |m_t| is the size of the edge in log-odds; a 'swing' is a sign change of m_t, and a persistent swing requires the new sign to hold for at least 8 points. Match-flow depiction: for 1701 the per-point series (edge, p1_win_prob, momentum) is saved to results/momentum_2023-wimbledon-1701.csv; the flow is read off the momentum trace against the set/game coordinates in the CSV (set 1: Djokovic; set 2: Alcaraz in the tiebreak; set 3: Alcaraz; set 4: Djokovic; set 5: Alcaraz). Parameter table (1701, all values from MLE on the supplied dataset, interval = fitting bounds, source: task dataset Wimbledon_featured_matches.csv, match 2023-wimbledon-1701): a = 0.123 [0.001, 0.4]; b = 0.000 [0, 1]; h = -0.100 [-1, 1]; g = 0.271 [0, 1.5]; fu = 0.179 [0, 1]; fd = 0.098 [0, 1]; k = 0.920 [0.15, 1.5]; cF = 0.125 [-1.5, 1.5]; cS = 0.367 [-1.5, 1.5]. Contextual base rates from the dataset (used to interpret the fitted values): server point-win rate 0.673; first-serve 0.754; second-serve 0.530; break-point conversion 0.351; server unforced-error rate 0.159 routine vs 0.169 on break points (exchange 4: pressure raises errors modestly for weaker players, can reverse for elite servers); double-fault rate 0.036 at routine points vs 0.023 at deuce/advantage (exchange 7: serve errors tick up modestly at deuce/ad for most players, direction player-dependent).

### Outcome Analysis

The model reproduces the match flow of the final. In 1701 the momentum trace is dominated by break-point events (g = 0.271 is the largest state driver; b = 0, so raw point wins carry no extra weight beyond what breaks and errors already convey). The trace is negative through much of set 1 (Djokovic's 6-1 run), crosses into positive territory during Alcaraz's set 2 and set 3 dominance (last-20-point averages +0.003 to +0.242 in those sets), turns negative in set 4 (last-20 average -0.217) when Djokovic won 6-3, and ends positive through Alcaraz's set 5. The model's point-probability Brier score is 0.2341 versus 0.2500 for the constant-rate baseline, i.e. it is a genuine (if modest) improvement in point prediction, which is the calibration standard the flow metric is built on. Per-set first-serve shares in the final (p1: 0.650/0.659/0.632/0.553/0.655; p2: 0.760/0.600/0.608/0.654/0.656) show Djokovic's first-serve percentage falling from 0.760 to 0.608 between sets 1 and 3 - consistent with the expert-calibrated fatigue pattern (first-serve percentage typically dips more than speed in long matches; exchange 9) - while Alcaraz stayed near 0.63-0.66. Limitations and biases: (1) parameters are per-match, so there is no cross-match sharing and small matches (122-200 points) have wide uncertainty on g and fu; (2) the AR(1) form is fixed by the expert-confirmed mechanism (short-lived, score-driven dips recovering within one or two games; exchanges 2, 10), so a longer memory would be untestable here; (3) the indicator is a constructed latent quantity - it is as 'momentum' as the data allow, and its sign flips are partially a function of the threshold k; (4) the serve effects are shared across players, so a player who serves fundamentally differently is only partly captured. No expert text appears in this model; the expert exchanges fixed only the qualitative mechanism (break-anchored swings, fatigue decay, pressure effects) which the MLE then quantified from the data.

## Subtask 2: Assess the coach's claim that swings in play and runs of success are random, using the model/metric from task 1, on all 

### Problem

Assess the coach's claim that swings in play and runs of success are random, using the model/metric from task 1, on all 31 provided matches.

### Analysis

The coach's null hypothesis, made precise: point outcomes are independent Bernoulli trials with probabilities determined only by the serving situation (serve type and server), i.e. no state dependence beyond the serve. The statistic is the number of sign flips of the momentum trajectory m_t computed with the full fitted model (the state recursion under the null keeps only the point-win feedback, since break-point, error and double-fault events are consequences of outcomes and cannot be exogenous drivers under the null). Test: Monte Carlo permutation test with 2000 resamples per match - draw point outcomes independently from the null Bernoulli probabilities (using the fitted cF, cS), re-run the momentum recursion, and compare the null flip count to the observed one. A small p-value means the observed flow is less choppy than random, i.e. it contains persistent structure the random model does not produce. This is a fair test because the null is the strongest version of the coach's position that is still testable on this data (it already allows for serve dominance, which the coach does not dispute).

### Modeling Process

Null: w_t ~ iid Bernoulli(p_t), p_t = sigmoid((cF*(I[serve_no=1]-1) + cS*(2*I[server=1]-1))/k) with cF, cS, k from the fitted match model. Statistic T = sum_{t=1}^{n-1} I[sign(m_t) != sign(m_{t-1})], where m_t is computed by the same recursion with the event terms (g, fu, fd, h) set to zero under the null. p-value = (#{resamples: T >= T_obs} + 1)/(2000 + 1), seed fixed for reproducibility. All quantities from code/model.py (perm_swings) and logs/coachtest.log, logs/robust.log; 2000 permutations per match.

### Outcome Analysis

The coach's claim is rejected for exactly 10 of 31 matches at the 5% level, and all 10 also at the 1% level: 1302, 1309, 1311, 1312, 1315, 1316, 1402, 1502, 1602, and the final 1701 (p < 0.001 each). For these matches the observed flow is significantly less churning than random: the player who is ahead in momentum tends to keep a run of points, and the random model over-predicts sign changes. The remaining 21 matches are consistent with randomness - their flow is as choppy as, or choppier than, independent points with serve odds, and momentum there is indistinguishable from noise. So the honest, data-based answer to the coach is nuanced: 'momentum' is real in roughly a third of these matches - and the final is one of them - but in most matches what looks like a swing is exactly the random streaking he describes. A secondary check on streaks supports the same picture: point runs of 4+ occur 302 times for p1 and 1854 total across all matches (many matches show both players producing several), so short runs are routine; but runs of 8+ are rare (20 across all 31 matches) and in every one of them the streaking player actually took a game, which is far more than chance would give for a pure random streak. Interpretation: the coach is right that most runs are noise; he is wrong that none of them signal anything - sustained (>= 8 point) runs and their associated breaks are the events that carry real information, and those are precisely the ones the permutation test flags in the 10 significant matches. Bias note: the test's power depends on the flip statistic, which is coarse; a more sensitive statistic (e.g. autocorrelation of wins) would likely flag more matches, so 10/31 is a conservative lower bound on non-random flow.

## Subtask 3: Develop a model that predicts when the flow of play is about to swing from one player to the other, identify which facto

### Problem

Develop a model that predicts when the flow of play is about to swing from one player to the other, identify which factors are most related, test it out-of-sample on other matches (the final 1701 held out), and state how generalizable the model is to other opponents, tournaments, surfaces and sports.

### Analysis

A swing is predicted at point t from information available at t. Features (all computed from the point data up to t): fs10 = first-serve rate over the last 10 serves, fs3 = last 3 serves, mom = current momentum indicator (task 1), serv = who is serving, bp = whether a break point is on, t = normalized match time. Labels: over the next 12 points, which player, if any, completes a run of 4+ consecutive points (classes: none, p1, p2, both). The 12-point horizon and 4-point run length are chosen so that a predicted 'swing' is something a coach could actually act on during a changeover or within a game, and so that both players are well represented in training (a momentum-based event definition would be dominated by one player's runs; the raw-run definition is symmetric). Method: multinomial logistic regression (L2), pooled over matches, fit on 30 matches and tested out-of-sample on 1701; leave-one-match-out cross-validation (31 folds) for generalization. Rationale for the method: small data (~6.6k training points), interpretable coefficients for the 'which factors' question, and a proper probability output for each of the four outcomes.

### Modeling Process

X_t = [fs10, mom, serv, bp, t] (5 features; fs3 retained in the matrix but dropped from the final feature set as redundant). Labels y_t in {0,1,2,3} as defined above, computed with a sliding 12-point window. Model: P(y_t = c | X_t) = softmax(X_t beta_c + b_c), MLE via sklearn LogisticRegression (liblinear/L-BFGS, max_iter=3000). Per-player binary versions (y=1 vs rest, y=2 vs rest) for AUC. Evaluation: (a) out-of-sample AUC for each player on 1701; (b) leave-one-match-out AUC across all 31 matches; (c) 4-class log-loss on 1701 OOS; (d) swing/no-swing accuracy on 1701; (e) top-decile/top-20% coverage of actual persistent (8+ point) swing start times. Code: logs/predict12.log (LOMO), logs/predict13.log (OOS + coverage), features saved in results/lr_pooled.npz.

### Outcome Analysis

The predictor is informative but not strong, which is the honest result. Out-of-sample AUC for 1701: 0.694 for predicting Alcaraz's upcoming 4+ runs and 0.676 for Djokovic's - clearly above chance but far from decisive. Leave-one-match-out AUC (the realistic generalization estimate): 0.572 (p1) and 0.603 (p2) averaged over 31 folds, with per-match range down to about 0.39 in the worst fold (the model can be anti-informative in individual short matches). 4-class OOS log-loss on 1701 is 1.164, and swing/no-swing accuracy is 0.559 against a base rate of 0.552 - so the model barely beats 'always predict a swing is coming' for the binary question, and the value is in the per-player direction. Top-10% coverage of actual 1701 persistent swing starts: 3 of 11 for the player whose momentum was positive, 0 for the other (the model's probability surface for the second player is flatter). The coefficients say the most related factor is current momentum (positive for the player it favors, negative for the other - runs beget short-term continuation), with smaller contributions from first-serve rate and match time; break-point status and server contribute weakly. This matches the expert's ordering (first-serve check first, errors and breaks as confirmation - exchange 8): in this data the momentum state, which already accumulates first-serve and break information, is the single most predictive available signal. Why the model performs poorly at times: (1) swings are partly unpredictable by design - the random component is large (task 2 showed 21 of 31 matches are consistent with pure noise); (2) the features are coarse - the dataset has no shot quality, placement, or body-language proxy, and no player-specific state, so the model cannot see a tactical adjustment coming; (3) 12-point windows overlap heavily, so labels are correlated and the effective sample is smaller than 6.6k. Factors to include in future models: shot-by-shot quality (winners/UEs by shot type), serve placement (width/depth are in the data but unused here), player age/fatigue proxies, and surface-specific serve baselines. Generalizability: within the provided data the model is a grass-court, elite men's Wimbledon product - the LOMO test over 31 matches is the strongest claim it supports (modest, ~0.57-0.60 AUC). It would transfer to other elite men's matches on grass with the same data schema; to other tournaments/surfaces the serve-odds structure and the relative weight of momentum would shift (clay favors rallies and the state dynamics would be slower) and the model must be re-fitted, though the feature set is still applicable; to women's matches the same feature set applies but parameters must be re-estimated since serve dominance is weaker; to other sports (e.g. table tennis) the architecture (latent strength + event-driven updates + Bernoulli outcomes) is the transferable part, while every coefficient, the event list, and the horizon would be sport-specific. The defensible advice: the model is a monitoring tool, not a forecaster - it raises the probability of an imminent swing by a factor of about 1.4-1.8 in the top decile, which is material for deciding when to press a changeover challenge or reset a player's focus, but not enough to bet a break point on.

### Problem

Memo for coaches: summarize the role of 'momentum' with the evidence, and how to prepare players to respond to events that affect the flow of play during a match.

### Analysis

This is a synthesis of the three modeling results into coaching-relevant statements, keeping every claim traceable to a number produced above. No new modeling is done here; the structure follows the problem's own memo requirements (role of momentum + preparation advice).

### Modeling Process

Not applicable (no formulas; this task consolidates: task 1 for the flow metric, task 2 for the randomness test, task 3 for the predictor). Parameter values quoted are those in the task 1 parameter table and the LOMO/OOS evaluation numbers in task 3.

### Outcome Analysis

Memo content. (1) Momentum exists but is narrow: in the 31 matches studied, point-by-point flow deviates from randomness in only 10, and the 2023 Wimbledon final is one of them. In the other 21, swings are statistically indistinguishable from luck. Coaches should therefore stop treating every run as meaningful and start treating sustained structure - runs of 8+ points and the breaks that accompany them - as the only runs that carry information. (2) What momentum actually is, per the model: a short-lived state driven mainly by break-point performance (largest coefficient) and by unforced errors, with a serving-advantage baseline of roughly +0.37 log-odds for the server and +0.13 for first serves over second (fitted 1701 values). The state fades quickly (per-point persistence a = 0.123, i.e. most of the edge decays within a handful of points), which matches the observed pattern that a dip in first-serve percentage recovers within the same or next service game unless it is fatigue-driven (exchange 10). (3) What to watch: the server's recent first-serve rate is the earliest leading cue (expert: check first serves first; the model's top feature is the momentum state which is built mostly from exactly these events). A drop in the opponent's first-serve share over the last ~10 serves is the single most actionable signal before a swing. (4) Preparation advice, grounded in the numbers: (a) train break-point service specifically - break-point conversion in this data is 35%, well below the overall point rate, and the model shows break-point events are the dominant swing driver, so a player who serves at a normal or higher level on break points removes the main swing mechanism against him; (b) accept that his own runs will often be noise - the 8+ point streaks are rare (20 in 31 matches), so a player down a run has not necessarily lost form; the correct response is to keep hitting to his normal targets, not to chase the deficit (expert: the trailing player's underlying level usually stays near baseline after a short run; exchange 5); (c) in long matches, plan a serve-pace management around the third set - first-serve percentage, not speed, is what erodes (exchange 9: a few mph slower, larger percentage drop, older players earlier), so preserving first-serve rate in sets 3-4 is the single highest-leverage preparation item for a player who will be facing a younger, faster opponent; (d) use the model's prediction as a monitor, not a bet - its best out-of-sample accuracy is ~0.68 AUC, so it flags windows worth paying attention to but cannot tell a player which shot to hit; (e) against a different opponent the absolute levels will change (the serve-odds and momentum weights are per-match), but the structure - watch the opponent's first serves, keep your own break-point serving stable, treat short runs as noise and 8+ runs as real - transfers, because it comes from the mechanism of how tennis points are won, not from these two specific players. (5) Limitations to state plainly to players: the model is built on one tournament and one surface; on clay or against women's draw the specific numbers (serve odds, decay rate) must be re-estimated, though the monitoring structure is the same; and the predictor's modest accuracy means the honest use is to sharpen attention at the right moments, not to change tactics on its output alone.
