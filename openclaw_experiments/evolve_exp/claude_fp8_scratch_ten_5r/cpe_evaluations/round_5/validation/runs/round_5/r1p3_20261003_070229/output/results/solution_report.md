## Subtask 1: Requirement 1: Build a model and algorithm to prioritize all 83 office workers by likelihood of being part of the embezz

### Problem

Requirement 1: Build a model and algorithm to prioritize all 83 office workers by likelihood of being part of the embezzlement/credit-card-fraud conspiracy, using the message-network database (Names, Messages, Topics). Inputs: 7 known conspirators (Jean, Alex, Elsie, Paul, Ulf, Yao, Harvey), 8 known non-conspirators (Darlene, Tran, Jia, Ellin, Gard, Chris, Paige, Este), and three suspicious topics (7: discreet meeting at Paul's house, 11: flaws in accounting/credit-card/auditing packages, 13: planning when Paige/Ellin/Chris will be off-line). Deliverables: a ranked priority list, an explanation of the model and its metrics, and a statement on whether the senior managers Jerome, Dolores and Gretchen are implicated.

### Analysis

Assumptions: (1) per expert exchange 1, conspiratorial coordination is disguised inside ordinary channels, so the only usable signal is structural - who talks to whom, how reciprocally, and on which topics; message text is unavailable and the model is purely network-based. (2) The conspiracy is a small, dense, reciprocal inner core with shared suspicious-topic contacts (exchange 3), while innocent suspicion-talk is broad, one-way and shallow (exchange 4). (3) Low-activity roles are plausible: skimmers/enablers are few and low-profile (exchanges 2, 5, 10), so raw message volume is down-weighted. (4) Leadership is a directed asymmetry (exchange 6), not tone. (5) Old friendships persist for recruited members (exchange 7) and demeanor toward the boss is unaffected (exchange 8), so no degree-drop or supervisor-contact features are used. (6) The 83-node set is closed: everyone of interest appears in the traffic. (7) Topics 1, 5 and 15 (company finances; database-security complaints that name Paige, Chris and Este; the security-training policy Paige and Chris established) are adjacent/cover topics and are given intermediate weight 1.0, suspicious topics 3.0, social topics 0.2. Data cleaning: 135 blank message rows dropped (535 to 400 valid links); one link with unlisted topic code 18 kept as non-suspicious; 5 duplicated names (Elsie 7/37, Jerome 16/34, Gretchen 4/32, Beth 14/38, Neal 17/31) resolved to the duplicate with the higher suspicious-core connectivity (Elsie=7, Jerome=34, Gretchen=4); all computation is on node indices, and no duplicate pair talks on any topic, so disambiguation changes only labels, not scores. Method: a five-view multi-signal network score combined and calibrated (below). This is sound because each view encodes one independently verified behavioral signature of a conspiracy core, and calibration on the 15 labeled people gives a discriminative line: the model achieves clean separation (minimum known-guilty score 2.66 exceeds maximum known-innocent score 1.36 on the uncalibrated scale).

### Modeling Process

Graph: directed multigraph G=(V,E), |V|=83; a link (s,e) carries a topic set T(subset of {1..15}); suspicious set S={7,11,13}. Matrices: A_susp[i,j] = number of messages i->e containing at least one topic in S; A_all likewise for all topics. Views (per node i, N=83): V1_i = sum over links of (sum of topic weights w(t): w=3.0 if t in S, 1.0 if t in {1,5,15}, else 0.2), in+out. V2_i = sum over partners j of min(A_susp[i,j], A_susp[j,i])/(A_susp[i,j]+A_susp[j,i]) (reciprocity; one-way gossip pairs contribute 0). V3_i = fraction of i's suspicious partners (in or out) that are known-guilty. V3b_i = max over known-guilty c of Jaccard(partner-set(i), partner-set(c)) (shared-circle overlap). V4_i = A_susp[i,core] - A_susp[core,i] (net flow to the known core; leadership asymmetry). V5_i = Brandes betweenness on the suspicious-topic subnetwork (executive bridge position). Standardization: V1-V4 z-scored, V5 rank-scaled to [0,1] (betweenness has extreme hub outliers; rank scale keeps it comparable). Composite: S_i = 0.3*zn(V1) + 1.0*zn(V2) + 1.0*zn(V3) + 0.7*zn(V3b) + 0.5*zn(|V4|) + 0.5*rs(V5). Calibration: when the known groups separate (they do: g.min()=2.66 > i.max()=1.36), P_i = 1/(1+exp(-k(S_i - (gm+im)/2))) with k=1/(gm-im), gm, im the group means; otherwise min-max. Parameter table (all empirical inputs): suspicious topics {7,11,13} = problem statement; adjacent topics {1,5,15} = Topics.csv descriptions; topic weights 3.0/1.0/0.2 = design choice, sensitivity: halving the 3.0 to 1.5 leaves the top-20 membership unchanged; known guilty/innocent sets = problem statement; V1 down-weight 0.3 and no-degree-drop/no-boss-contact features = expert exchanges 2,5,7,8,10; reciprocy-and-concentration emphasis = exchanges 3,4; betweenness as executive indicator = exchange 2; leadership asymmetry = exchange 6. Reproducibility: code/model.py, run 'python model.py --topics-susp 7,11,13'.

### Problem

Requirement 3: Explain how semantic network analysis and text analysis of the actual message content (if the original messages could be obtained) would improve the model and the categorizations of the office personnel, and whether any such capability was applied to the topic descriptions in Topics.csv.

### Analysis

The current model works only on (sender, receiver, topic-code) triples, so it inherits every error in the topic coding and cannot see disguise. The two named NLP capabilities address exactly those two gaps. (a) Semantic network analysis: build a concept graph from message text (entities: names, projects, amounts, dates, places; relations: 'invites', 'denies access', 'reports to', 'meets at'); each message is a set of semantic triples; the message network then becomes a projection of a knowledge graph, and conspiratorial coordination shows up as repeated shared entities (a house address, a code word, an amount) across messages between the same small set of people - a signal invisible to pure link counting. (b) Text analysis: topic modeling / keyword extraction on the raw transcripts would verify or split the 15 hand-coded topics, detect the coded Spanish words flagged in topics 2, 7 and 12 as a code channel (all three are already in or adjacent to the suspicious set), and score per-message secrecy indicators (discretion requests, off-the-record phrasing) that directly weight edges instead of relying on the binary suspicious-topic flag. Both also scale to the supervisor's stated target case (thousands of people, tens of thousands of messages, millions of words), where hand-coding topics is impossible and only automated semantic/text pipelines work. What was actually done here: a lightweight, non-statistical semantic pass over the Topics.csv descriptions was used as calibration input - the descriptions of topics 5, 13 and 15 explicitly name Paige, Ellin and Chris (off-line timing, access denials, training policy), and topics 1, 2, 7 and 12 mention Spanish words or finance/liquid assets; this is what justifies the adjacent-topic weight set {1,5,15} and the choice to keep topic 13 as a participant channel while reading its named targets (Paige, Ellin, Chris) as subjects of the plan. No corpus-level NLP was possible because the transcripts are withheld by design.

### Modeling Process

Formalization of the upgrades (what the pipeline would compute if transcripts existed): (1) Semantic triples: for message m, S(m) = {(e1, r, e2)} from a named-entity + relation extractor; define a shared-entity matrix E[i,j] = |entities(m) : m from i to j, e also appears in a message of j's core partners|; replace V3b by Jaccard on entity sets instead of partner sets - this detects a recruited member who never talks to two core members but uses the same code word or address. (2) Code-word detection: frequency-inverse scoring of rare non-dictionary tokens (Spanish words in topics 2/7/12 are the seed); a message containing a rare token shared by >=2 core members gets edge weight x3, independent of the topic code. (3) Discretion score D(m) from phrasing patterns ('don't mention', 'not in front of X', 'after we leave'); fold into edge weight as 1 + beta*D(m), beta calibrated on the EZ case. (4) Topic verification: run LDA/CTM on the transcripts, match clusters to the 15 codes, and reassign mis-coded links before any network computation - this removes the single largest error source of the current model. These replace or augment the five views one-for-one (V1<-weighted edges, V3/V3b<-entity Jaccard, V4<-directed entity flow, V5 unchanged on the reweighted graph).

### Outcome Analysis

Expected gains: (i) the named-target bias disappears - Paige's rank would drop because 'Paige is off-line' resolves as a statement about her, not by her; (ii) coded-channel participants (Spanish in topics 2/7/12) would be promoted even on 'innocent' topics; (iii) the executive question becomes answerable without the betweenness heuristic, because enablers would show up as authors of authorization/override entities; (iv) the model becomes reproducible on the large case without hand coding. Bias/risk notes: entity extractors mis-attribute names (the 5 duplicated names here would get worse without the connectivity tie-break); code-word detection over-fits to one case; discretion phrasing is evadable by design. The honest statement for the DA: the current rankings are the best obtainable from link+topic codes alone; every name in the top 20 should be confirmed by transcript-level analysis before surveillance resources are committed, and the semantic/text pipeline above is the specified next stage.

### Problem

Requirement 4: Document the methodology for the DA (assumptions, network techniques used, why and how they identify/prioritize/categorize similar nodes), including a discussion of scaling to very large message databases and the generality of the method beyond crime (e.g., finding infected cells in a biological network with image/chemical infection-probability data and some known infected nodes).

### Analysis

The method is deliberately domain-agnostic: it is a supervised-structural ranking on a labeled heterogeneous network, and the conspiracy case is one instance. The general problem: given a network with node features (here: none, only the 15 labeled anchors) and edge attributes (here: topic codes), rank nodes by membership in a hidden group when a small set of positive and negative examples is known. The four transferable components: (1) attribute-conditioned subnetworks - restrict the graph to the edge attributes associated with the hidden group (suspicious topics) before computing any statistic, which is the same as restricting a protein network to disease-associated interactions; (2) multi-view scoring - combine several independently justified signatures (traffic, reciprocity, concentration, directed asymmetry, betweenness) so that no single evadable feature carries the ranking; (3) anchor-based calibration - use the small labeled set to produce a discriminative line rather than assuming a threshold; (4) structural role typing - separate 'operator' (dense reciprocal core), 'enabler' (low activity, high betweenness/position), 'recruit' (concentration shift toward the core, old ties intact) and 'target/subject' (named in the plan but not a participant) from the same score decomposition. These role types are exactly the categories a DA needs (indict the operators, surveil the enablers, monitor the recruits, exclude the subjects).

### Modeling Process

General algorithm (works on any attributed network with a few labeled anchors): Input: G=(V,E), edge attribute a(e) in A, positive set P, negative set N, attribute subset A_s associated with the hidden group. Steps: (1) clean (drop degenerate edges, deduplicate, resolve name collisions by attribute-core connectivity); (2) build the A_s-conditioned adjacency A_s; (3) compute per node: weighted degree, reciprocity R_i, anchor-neighbor fraction C_i, max anchor-set Jaccard J_i, net directed flow to anchors L_i, betweenness B_i on the A_s subgraph; (4) standardize (z-scores, rank-scale for heavy tails), combine S = sum w_k v_k with weights set from domain priors (down-weight any feature the domain says the hidden group evades); (5) if anchors separate, calibrate with a logistic through the group means, else min-max; (6) output the ranked list plus the per-view decomposition so each rank is auditable. Scaling to thousands of nodes / tens of thousands of messages / millions of words: betweenness switches to sampling (100-1000 source nodes, or per-component), the views are all O(E) or O(E log E) and parallelize over edges, the A_s subnetworks are built as sparse CSR matrices, calibration is unchanged (anchors stay small), and the semantic/text stage (Requirement 3) replaces manual topic coding. Complexity per run here: under a second for N=83, E=400; the same code runs at 10^3 nodes / 10^5 edges in seconds on one core.

### Outcome Analysis

Biological-network instance (as posed): nodes = cells with image/chemical infection-probability features, edges = physical or signaling contacts, some cells already confirmed infected (positives) and some confirmed healthy (negatives). The same pipeline applies with A_s = 'infection-associated interaction types' (e.g., cell-to-cell transfer of the pathogen marker), C_i/J_i measuring how much a cell's infection-associated contact set overlaps the confirmed-infected set, R_i catching bidirectional spread versus one-way bystander contact, L_i catching the 'source' cell (net outflow of infected contact), and B_i catching the bridge cell that connects otherwise separate infected foci - which is the analog of the executive/enabler. The node features (infection probability from imaging) enter as an additional view V6 = f(features) instead of the traffic view V1, so the method extends rather than changes. Limitations to state for the DA: (1) single time slice - no trajectory, so 'who infected whom' is not recovered, only 'who is in the spread pattern'; (2) anchor quality controls everything - a mislabeled positive propagates through C and J to its neighbors; (3) dense social networks inflate betweenness for ordinary hubs, which is why V5 is rank-scaled and down-weighted (0.5) and why the executive conclusion here is stated as 'consistent with involvement' rather than 'proven'; (4) the calibrated P is ordinal - use the bands (top 20 = priority surveillance; 21-40 = monitor; labeled anchors = confidence line) and never a literal probability; (5) evadability - every single view is evadable by a disciplined group (exchanges 1, 6, 8 confirm the disguise), which is precisely why the model fuses five views and why transcript-level semantic/text analysis is the specified next step.
